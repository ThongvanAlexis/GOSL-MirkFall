### Locked Decisions

#### Moteur et versions

- `flutter_map` pinné à **7.0.2**, pas 8.x : parité stricte avec le code validé par le POC. Toutes les nouvelles dépendances strictement pinnées (règle projet).
- Les 6 packages sont ajoutés dans un plan Wave 0 dédié avec audit `DEPENDENCIES.md` + `flutter pub deps` transitives + CI verte, avant tout code.

#### Périmètre d'import autorisé (remplace `check_avoid_maplibre_leak`)

- `package:flutter_map` et `package:latlong2` autorisés uniquement dans : `lib/infrastructure/map/**`, `lib/presentation/widgets/fog_layer.dart`, `lib/presentation/widgets/fog_clip_path.dart`, `lib/presentation/screens/map_screen.dart` (composition du widget).
- Interdits partout ailleurs, en particulier `lib/domain/**` (gate `check_domain_purity` existant) et `lib/application/**`.
- Justification : l'invariant FOG-07 impose que `MapCamera.of(context)` soit lu dans le `build()` d'un enfant direct de `FlutterMap`. Le `FogLayer` est donc structurellement un consommateur flutter_map, on l'assume et on le liste explicitement plutôt que de l'abstraire artificiellement.

#### Seam `MirkRenderer` et `MirkPaintContext`

- La signature `paint(Canvas, Size, MirkPaintContext)` est conservée : Phase 10 audite ce seam, il doit rester pur (pas de type flutter_map dans le domaine).
- `MirkPaintContext` est étendu **une seule fois** dans cette phase (précédent Plan 09-02) avec les données dérivées de la caméra dont les renderers ont besoin : `pixelOrigin` (x, y) déjà sign-flippé si Android, `zoomScale = pow(2, zoom - referenceZoom)`, `canvasOffset`, et une fonction de projection `LatLng → Offset` exposée sous un type domaine (record ou callback typé), jamais `MapCamera` lui-même.
- Le `FogLayer` construit ce contexte à partir du snapshot `MapCamera` unique, puis délègue au `MirkRenderer` actif via le provider existant. Le `FogLayer` est la frontière ; le renderer ne connaît pas flutter_map.

#### Les 4 variants builtin

- Seul `atmospheric` (shader) est validé same-canvas par le POC. Il devient l'implémentation portée de `fog_layer.dart` / `_FogPainter`.
- `solid_fill`, `candlelight`, `heavenly_clouds` doivent rester compilables et sélectionnables (gate `check_mirk_variant_file_count`) et passer par le même `clipPath` disques + même frame Canvas. Pour `heavenly_clouds` (noise animé) appliquer le même mécanisme `pixelOrigin` / `zoomScale`. Aucune régression visuelle ne doit apparaître sur `solid_fill` qui n'a pas de noise à ancrer.
- Si l'adaptation de `candlelight` / `heavenly_clouds` dépasse le budget de la phase, elle est reportée en Phase 13 avec note explicite dans `deferred-items.md`, mais les variants ne sont jamais supprimés.

#### Style et assets

- Brancher `assets/maps/style.json` via `ThemeReader` de `vector_tile_renderer`. Si des expressions ne sont pas supportées, adapter le style (via `tool/prepare_style.dart` existant) plutôt que de forker le renderer. Fallback documenté : `ProtomapsThemes.lightV3()` pour `standard` le temps d'ajuster.
- `StyleRewriter` (réécriture des URI PMTiles dans le style pour MapLibre) devient probablement inutile : supprimer si plus aucun appelant, avec ses validators et le gate `check_style_no_external_url` conservé côté asset.
- `assets/maps/glyphs` et `sprites` : supprimer si `vector_tile_renderer` ne les consomme pas, après vérification de l'impact sur le rendu des labels.

#### Persistance et perf

- Les disques viennent de `DriftRevealedDiscStore` uniquement. Pas de repo mémoire parallèle.
- Le `SdfCache` (clé quantifiée PERF-08) est porté tel quel. La courbe de coût rebuild avec des volumes de disques persistés plus grands que ceux du POC (caveat #6) est mesurée pendant l'UAT via le logger `infrastructure.mirk.sdf` et notée pour Phase 10.
- Le probe `frame_delta` (PERF-07) et les loggers `fog_transform` / `sdf_rebuild` / `wisp_transform` / `dev_marker` sont portés mais **actifs uniquement en verbose logging** (flag `--dart-define=DEBUG=true` ou toggle du debug menu). En production, seuls erreurs et events métier (règle CLAUDE.md §Logging).

#### Constantes

- Renommer les `kPoc*` en convention MirkFall dans `lib/config/constants.dart` : `kMirkFogReferenceZoom = 13.0`, `kMirkFogNoiseTilePx = 384.0`, `kMirkWisp*` (drift 1.5 m/s, cap 200, warm-up 5 s). ## Summary

Le POC `mirk-poc-debug` (HEAD `46da8e3`, code identique à `90c9321` — le delta est documentaire) a validé l'architecture same-canvas : `FlutterMap(children: [VectorTileLayer, FogLayer, CircleLayer])` où le `FogLayer` lit `MapCamera.of(context)` une seule fois par build, translate le canvas de `-canvasOffset` (FOG-13), clippe par `viewportRect − ∪ disques` projetés via `camera.latLngToScreenPoint`, et peint le shader avec `uPixelOrigin = camera.pixelOrigin` (sign-flippé en Y sur Android, FOG-23) et `uZoomScale = 2^(zoom − 13)` (FOG-19). Le fichier de référence est `mirk-poc-debug/lib/presentation/widgets/fog_layer.dart` (954 lignes, dont ~60 % de commentaires de rationale) + `fog_clip_path.dart` (115 lignes). Le diff donor est étroit : seuls `fog_shader_uniforms.dart` (slot 41), `atmospheric_fog.frag` (formule worldPx), `wisp_particle.dart` et `wisp_particle_system.dart` (réécriture m/s) divergent ; `revealed_sdf_builder.dart`, `tile_cell_iteration.dart`, `mirk_projection.dart`, `animation_helpers.dart` et `reveal_disc.dart` sont identiques au nom du package près.

Côté MirkFall, la migration touche un périmètre bien délimité : l'adapter `maplibre_map_view.dart` (595 lignes, seul import `maplibre_gl`), `mirk_overlay.dart`, `offscreen_fog_renderer.dart` (zéro appelant), 4 méthodes vestiges de `MapView` (`markVisited`, `add/update/removeFogImageSource` — zéro appelant hors adapter et `FakeMapView`), `PmtilesSource` (URI → chemin), le style JSON (compatible `ThemeReader` à une exception près : la couche `mirk_fog` de type `background` serait peinte en noir opaque car `ThemeReader` ignore `background-opacity`), et la composition de `MapScreen`. Les contrôleurs Phase 07 (`MapCameraController`, `CountryResolverController`, `MapViewport`, `MapViewportZoom`) consomment uniquement `viewportUpdates`, `queryViewport`, `queryViewportBounds`, `showMap`, `moveCameraTo`, `setUserLocation`, `setFollowMeEnabled` : ils ne bougent pas si l'adapter flutter_map respecte ce contrat.

Trois écarts entre CONTEXT.md et le code doivent être arbitrés par le planner (détail §Contradictions) : (1) le code de clôture du POC n'applique PAS `uSdfRect` identité sur Android mais `(0, 1, 1, −1)` (FOG-21, même racine que FOG-23 — à porter ensemble) ; (2) `wisp_particle*.dart` du POC importent `package:latlong2`, hors du périmètre d'import décidé (`lib/infrastructure/mirk/wisp/**` n'y figure pas) ; (3) `MirkRenderer` a aujourd'hui 4 membres (le getter `sdfViewport`, vestige BUG-014), pas 3.

**Primary recommendation:** Porter `fog_layer.dart` + `fog_clip_path.dart` + `sdf_cache.dart` + `fog_shader_uniforms.dart` + `atmospheric_fog.frag` + `wisp_*` du POC quasi verbatim, en scindant `FogLayer` en un widget pur à injection constructeur (portable avec les 27 tests POC) et un connecteur Riverpod fin ; câbler l'adapter `MapView` sur `MapController.mapEventStream` / `MapOptions.onMapReady` ; retirer `mirk_fog` du style ; isoler le cache tuiles par archive PMTiles.

**Tunables aujourd'hui.** `lib/application/tunables/mirk_runtime_tunables.dart` est un `ChangeNotifier` singleton (`MirkRuntimeTunables.instance`) que `AtmosphericMirkRenderer._paintShader` (atmospheric_mirk_renderer.dart:403-449) et `HeavenlyCloudsMirkRenderer` lisent **à chaque paint** avant `FogShaderUniforms.setAll(...)`. `mirk_tuner_sheet.dart` écrit dans le singleton via `AnimatedBuilder(animation: MirkRuntimeTunables.instance)`. `MirkFogOpacityPref` (slider densité du burger menu, persisté SharedPreferences) écrit `opacityFar/Mid/Near`.

**Ce qui doit changer.** Le POC alimente les 20 floats via une `Map<String,double> _mirkFogConstants` statique (fog_layer.dart:284-305) figée sur les constantes : porté tel quel, le tuner cesserait d'agir. Deux options compatibles avec la décision "FogLayer délègue au MirkRenderer actif" :

- **Recommandé :** garder la lecture des tunables **dans le renderer** (comme aujourd'hui). `AtmosphericMirkRenderer.paint(canvas, size, ctx)` appelle `FogShaderUniforms.setAll(shader, resolution: size, time: ctx.sessionElapsedSeconds…, pixelOrigin: ctx.pixelOrigin, zoomScale: ctx.zoomScale, sdfRect: ctx.sdfRect, …tunables…)`. Le `FogShaderRenderer` abstrait du POC (seam de test `RecordingFogShaderRenderer`) devient alors l'API interne du renderer atmospheric, pas du `FogLayer`. Les tests POC `fog_layer_test.dart` / `fog_pixel_origin_decomposition_test.dart` / `fog_zoom_invariant_basis_test.dart` s'adaptent en injectant le renderer enregistreur via la factory de renderer plutôt que via `FogLayer(shaderRenderer:)`.
- Alternative : `FogLayer` construit la map depuis `MirkRuntimeTunables.instance` à chaque build — mais `lib/presentation/widgets/fog_layer.dart` importerait `lib/application/tunables` (couplage UI → application acceptable, moins propre).

Attention `uTime` : MirkFall passe aujourd'hui `context.sessionElapsed` (Duration du Ticker) ; le POC passe un Stopwatch lu à chaque `paint()`. Les deux sont "par référence" au sens où la valeur est fraîche à chaque paint ; garder un Stopwatch dans le painter (invariant 10) et exposer `sessionElapsed` dérivé dans le contexte (les renderers CPU `candlelight` / `heavenly` en dépendent).

**Extension unique recommandée (domaine pur, sans type flutter_map) :**

```dart
// lib/domain/mirk/mirk_paint_context.dart — extension unique Phase 09.1
typedef GeoPoint = ({double latitude, double longitude});          // déjà la forme de MapView.markVisited
typedef ScreenProjector = Offset Function(GeoPoint point);          // dart:ui Offset autorisé en domaine (précédent Canvas/Size)
typedef MetersToPixels = double Function(double meters, double atLatitude);

@freezed
abstract class MirkPaintContext with _$MirkPaintContext {
  factory MirkPaintContext({
    required double zoomLevel,
    required double pixelRatio,
    required Duration sessionElapsed,
    required MirkViewportBbox viewportBbox,
    required List<RevealDisc> discs,
    Fix? currentFix,
    // --- Phase 09.1 ---
    required ({double x, double y}) pixelOrigin,        // camera.pixelOrigin, .y négatif sur Android (FOG-23)
    required double zoomScale,                           // pow(2, zoomLevel - kMirkFogReferenceZoom)
    required (double, double, double, double) sdfRect,   // iOS (0,0,1,1) ; Android (0,1,1,-1) (FOG-21)
    required ({double dx, double dy}) canvasOffset,      // informatif : translation MobileLayerTransformer déjà compensée
    required ScreenProjector projectToScreen,            // camera.latLngToScreenPoint, frame identité (post-translate)
    required MetersToPixels metersToPixels,
  }) = _MirkPaintContext;
}
```

Notes : Freezed accepte des champs de type fonction (égalité par identité ; `shouldRepaint` du painter compare de toute façon `camera`/`discs`/`sdfImage`). Si le planner préfère éviter les closures dans un Freezed, une classe immuable manuelle est acceptable (le contract test `mirk_paint_context_test.dart` s'adapte). Retirer `sdfViewport` de `MirkRenderer` (C3). Les renderers CPU remplacent `MirkProjection.latLonToScreen(...)` par `context.projectToScreen(...)` et `buildViewportFogClipPathFromDiscs(...)` par une variante prenant la projection + `metersToPixels` (ou par le `computeFogClipPath` du POC déplacé sous `lib/infrastructure/mirk/` avec la projection injectée — il n'a alors plus besoin de `flutter_map`). Un seul clip path par frame, même géométrie pour les 4 variants : soit le `FogLayer` l'applique avant de déléguer (recommandé : le renderer peint alors `Offset.zero & size`), soit chaque renderer garde son clip via la même fonction. Le premier choix simplifie les 4 renderers et garantit l'invariant "même clipPath disques".

## 7. Persistance des disques et SDF

Chaîne actuelle : `RevealStreamingController.onFix` → buffer (2 s / 20 fixes) → `RevealedDiscStore.addDisc` (`DriftRevealedDiscStore`, schéma v6) ; lecture `discsInViewportProvider(viewport:)` (autoDispose, famille clé `MirkViewportBbox`) → `store.discsInBbox(sessionId, bbox)` ; `mapViewportProvider` (keepAlive) → `MapView.viewportUpdates` throttle 50 ms → `queryViewportBounds()` ; `MirkOverlay` watch les 4 providers + garde `_lastKnownDiscs` (BUG-012 anti-strobe) ; `activeMirkRendererProvider` fournit le renderer.

- **Requête DB** : rester sur `mapViewportProvider` (bbox throttlé, issu de `mapEventStream`) et **non** sur le bbox caméra par frame (sinon une nouvelle instance de famille + requête SQL par frame). Garder le pattern `_lastKnownDiscs`. Recommandation : requêter un bbox **paddé** (viewport élargi d'un demi-viewport dans chaque direction) pour que les disques en bordure existent déjà quand le pan les fait entrer, entre deux rafraîchissements throttlés ; `RevealDisc.intersectsBbox` + `SdfCache` filtrent ensuite.
- **Peinture** : le clip path et la projection des wisps utilisent le snapshot `MapCamera` (exact, par frame) ; le SDF (`SdfCache.getOrBuild(discs, viewportBboxFromCamera)`) est asynchrone : le painter peint avec la dernière image résolue (`_currentSdfImage`, fog_layer.dart:251-255, 345-353) — pendant un pan rapide le halo SDF est légèrement en retard, le clip path est exact. Approuvé sur device par le POC.
- **Coût rebuild (caveat #6)** : clé `SdfCache` quantifiée à 1e-4° (~11 m) ; à z15 (~4.8 m/px) le bbox change tous les ~2-3 px de pan → rebuild quasi par frame pendant un pan continu (POC : médiane 68/s, max 121/s, rebuild sub-ms avec < 50 disques). MirkFall mesuré (BUG-010 doc, desktop) : ~28 ms à 100 disques, ~211 ms à 1 000, ~2.4 s à 10 000. **Le `SdfCache` seul ne suffit pas** avec des volumes persistés : garder le debounce viewport-only de 200 ms (`kMirkFogSdfViewportDebounceMs`, BUG-012) devant `getOrBuild` (rebuild immédiat sur changement de disques, différé sur changement de viewport seul), et s'assurer qu'un seul build est en vol (`_pendingSdfBuild`, fog_layer.dart:255, 320). Mesure UAT via `Logger('infrastructure.mirk.sdf')` (`SdfRebuildLogger.recordRebuild(elapsedMs, discCount, intersectingDiscCount)`), levier Phase 10 : index spatial (TODO `revealed_sdf_builder.dart:103`). Le shader tolère un SDF stale mais **pas** un SDF absent (première frame sans fog : POC accepte ; MirkFall a `MirkInitialRevealFade` pour le premier reveal).
- `SdfCache` : porter tel quel (constructeur `SdfCache({required SdfRebuildLogger rebuildLogger, RevealedSdfBuilder? builder})`, `getOrBuild`, `dispose` qui libère la `ui.Image`). Il remplace dans les renderers `_hashDiscList/_hashViewport/_triggerSdfRebuild/_sdfViewport/_computeSdfRect` ; `test/infrastructure/mirk/sdf_debounce_test.dart` est à réécrire sur le nouveau point de debounce.

## 11. Gotchas plateforme

- **FOG-23 (Android, permanent)** — `fix(android): sign-flip pixelOrigin.y to cancel GPU-codegen noise inversion` (POC `3d74694`, 2026-05-15) + docstring auto-portante `a73a0cc`. Symptôme sans le fix : stripes horizontales / noise dérivant à l'opposé du pan sur Pixel 4a ; toutes les valeurs Dart étant identiques entre plateformes (rollups `fog_transform` : sx = sy = 1, shear 0, `FlutterFragCoord` Y-down partout), l'inversion est attribuée au codegen impellerc → Vulkan/SPIR-V de `worldPx.y = fragCoord.y + uPixelOrigin.y`. Correction Dart-only, pas de nouvel uniform (trois tentatives d'ajout d'uniform près du sampler ont cassé Impeller-Metal côté iOS).
- **FOG-21 (Android, même racine)** — `uSdfRect = (0, 1, 1, -1)` sur Android : Impeller-Vulkan échantillonne la `ui.Image` en V-up ; sans le fix, le halo SDF est miroir vertical par rapport au trou du clip (cf. C1). Sûr parce que les 4 composantes sont des scalaires indépendants (slots 37-40, BUG-014 it. 2).
- **Impeller** (docs.flutter.dev/perf/impeller, consulté 2026-09-09) : iOS = Impeller seul (Metal), pas d'opt-out ; Android API 29+ = Impeller par défaut (Vulkan, repli OpenGL ES sur les appareils sans Vulkan ; opt-out `io.flutter.embedding.android.EnableImpeller=false` encore documenté). `AndroidManifest.xml` MirkFall ne porte aucune meta-data Impeller → défaut. Pixel 4a (API 33, Adreno 618) : le code POC parle d'"Impeller-Vulkan observé", le VERDICT de "Skia fallback non vérifié" → disposition réellement non établie (Open Question ; AB test Phase 15). Le `.frag` garde `#ifdef IMPELLER_TARGET_OPENGLES` pour le repli GLES. `FragmentShader` + `CustomPaint` enfant de `FlutterMap` : validé POC sur iPhone 17 Pro (médiane 1.2 ms) et Pixel 4a (médiane 25.6 ms, p95 391 ms attribué au device/GC) — HIGH.
- **Workaround iOS Phase 07 à retirer** : `map_screen.dart:334-361` (`_onMapReady` post-frame + docstring issue maplibre #717), `map_view.dart:45-64` (docstring `moveCameraTo`/`jumpCameraTo` SIGABRT), `map_screen.dart:214-233` (commentaire "animateCamera → SIGABRT" ; l'idée "caméra initiale par constructeur" reste valable via `MapOptions.initialCenter/initialZoom`, sans la justification crash). `docs/phase-07-ios-animate-camera-crash.md` reste comme historique.
- **Natif** : aucune ligne MapLibre dans `ios/Podfile`, `ios/Runner/Info.plist`, `android/app/build.gradle.kts`, `AndroidManifest.xml` ; `ios/Podfile.lock` est le placeholder Windows (régénéré en CI). `INTERNET` permission reste (téléchargements). `check_platform_manifests` non impacté. JDK 21 en CI Android : optionnel de revenir à 17.
- **`dart:io` `Platform.isAndroid`** dans `fog_layer.dart` : sur Windows desktop → branche iOS (identité) ; correct pour les tests de logique.
- **Isolates `vector_map_tiles`** (`concurrency` défaut 4) : OK sur les trois plateformes ; en widget test le rendu passe (POC 218 tests verts).

### Anti-patterns à éviter

- **`RepaintBoundary` autour du `FogLayer`** : isole du signal de repaint des tuiles → une frame de retard (BUG-014 recréé dans Flutter). POC : verrouillé OUT.
- **Re-lire `MapCamera.of(context)` / `canvas.getTransform()` dans le painter** : multi-snapshot → jitter (FOG-07/12).
- **Décomposer / moduler `uPixelOrigin` côté Dart** (FOG-17a) : SNAP visible à chaque wrap (FOG-18 l'a éliminé ; fp32 exact jusqu'à 16.7 M px).
- **Stocker les wisps en pixels écran** (`kMirkFogWispInitialSpeedPx = 18`) : à z15 ≈ 86 m/s ; dérive au zoom.
- **Copier le Stopwatch** ou capturer `uTime` au build : noise figé.
- **Construire le `Theme` par build** : churn de rebuild dominant à z15 (POC RESEARCH §Anti-patterns).
- **`setState` dans le tick** : le POC utilise `CustomPainter(repaint: Listenable)` notifié par le Ticker — la peinture court sans passer par `build` (contrairement à `MirkOverlay._onTick` qui fait `setState`).

## Common Pitfalls

### Pitfall 1 : `mirk_fog` background opaque
**Ce qui casse :** carte entièrement noire. **Pourquoi :** `ThemeReader._toBackgroundTheme` ignore `background-opacity`. **Éviter :** retirer la couche du style et de `kStyleLayerOrder` (C7). **Signal :** écran noir dès le premier rendu, même sans session.

### Pitfall 2 : clé `TileProviders` ≠ `source` du style
**Ce qui casse :** carte grise en release (assert debug seulement, `vector_tile_layer.dart:141-150`). **Éviter :** constante `kMapStyleSourceKey = 'mirkfall_map'` + test qui lit `assets/maps/style.json` et vérifie `theme.tileSources == {kMapStyleSourceKey}`.

### Pitfall 3 : cache tuiles partagé entre archives au hot-swap pays
**Ce qui casse :** après `showMap(fra)` ou retour au monde, des tuiles z0-2 de l'archive précédente sont servies depuis `<temp>/.vector_map` (clé `source/z/x/y/theme.id`, sans identité d'archive) ; en mémoire, le `VectorTileLayer` garde ses caches si le widget n'est pas recréé. **Éviter :** `cacheFolder` par archive (sous-dossier `alpha3`/`world`) + `ValueKey(archiveKey)` sur `VectorTileLayer` ; fermer l'ancien `PmTilesArchive` après le swap ; ne jamais fermer avant que le nouveau layer soit monté (le provider en vol lit encore le fichier).

### Pitfall 4 : `MapController` utilisé avant le premier rendu
**Ce qui casse :** `Exception('You need to have the FlutterMap widget rendered at least once')` dans `queryViewport` / `move` (openForSession au boot). **Éviter :** publier l'adapter dans `onMapReady` ; try/catch dans `queryViewport*` (déjà présent côté `MapViewport`) ; `MapCameraController.openForSession` est appelé après publication → OK.

### Pitfall 5 : rebuild SDF par frame pendant le pan avec des centaines de disques
**Ce qui casse :** frame > 100 ms sur Pixel 4a, jank sur iPhone. **Pourquoi :** clé bbox quantifiée à 11 m ≈ 2-3 px à z15 ; `buildFromDiscs` ~28 ms @100 disques. **Éviter :** debounce 200 ms viewport-only devant `getOrBuild`, un seul build en vol, dernière image conservée ; mesurer via `infrastructure.mirk.sdf` (caveat #6) ; index spatial en Phase 10 si nécessaire.

### Pitfall 6 : requête DB keyed sur le bbox caméra par frame
**Ce qui casse :** `discsInViewportProvider(viewport:)` recrée une famille + une requête SQL par frame. **Éviter :** garder `mapViewportProvider` (throttle 50 ms) comme clé, bbox paddé ; peindre avec le snapshot caméra.

### Pitfall 7 : disques en bordure absents entre deux rafraîchissements
**Ce qui casse :** trous qui "poppent" au bord pendant un pan. **Éviter :** padding du bbox de requête (½ viewport), cf. §7.

### Pitfall 8 : oublier FOG-21 en portant FOG-23
**Ce qui casse :** Android : halo watercolour miroir vertical, trou du clip correct. **Éviter :** porter les deux branches `Platform.isAndroid` ensemble, avec la docstring `a73a0cc`.

### Pitfall 9 : `latlong2`/`flutter_map` importés hors périmètre
**Ce qui casse :** nouveau gate rouge, `check_domain_purity` inchangé mais seam fuité. **Éviter :** `GeoPoint` record dans les wisps (C2), `MirkPaintContext` avec callbacks.

### Pitfall 10 : `Theme` / `Logger` collisions de noms
**Ce qui casse :** `Theme` (Material) vs `Theme` (vector_tile_renderer), `Logger` (`package:logging`) vs `Logger` (vector_tile_renderer). **Éviter :** `import 'package:vector_tile_renderer/vector_tile_renderer.dart' as vtr;` et ne passer aucun logger vtr (ou un `vtr.Logger` préfixé).

### Pitfall 11 : `dynamic` dans `ThemeReader.read(Map<String, dynamic>)`
**Ce qui casse :** `strict-raw-types`/`strict-inference` MirkFall. **Éviter :** `jsonDecode` → `as Map<String, dynamic>` avec commentaire justificatif (frontière API tierce), comme `country_catalog` le fait pour `Map<String, Object?>`.

### Pitfall 12 : `check_avoid_remote_pmtiles` devient inerte
**Ce qui casse :** MAP-05 n'est plus mécaniquement garanti (le nouveau code n'émet plus `pmtiles://`). **Éviter :** étendre le regex à `fromUri|fromSource\(\s*['"]https?://` et tester `PmtilesSource` (aucun résultat ne commence par `http`).

### Pitfall 13 : loggers diag en production
**Ce qui casse :** ~5 rollups JSONL/s dans `<app_docs>/logs` (règle CLAUDE.md §Logging). **Éviter :** `start()` conditionné au flag verbose (`--dart-define=DEBUG=true` ou toggle debug menu) ; les `record*` restent des no-op quand non démarrés (`stop()` idempotent dans le POC).

## Code Examples

### Clip path exact (POC `fog_clip_path.dart:71-109`)

```dart
ui.Path computeFogClipPath({required MapCamera camera, required List<RevealDisc> discs, Offset canvasOffset = Offset.zero}) {
  final cameraSize = Size(camera.size.x, camera.size.y);
  final viewportRect = Rect.fromLTWH(-canvasOffset.dx, -canvasOffset.dy, cameraSize.width, cameraSize.height);
  final worldPath = ui.Path()..addRect(viewportRect);
  if (discs.isEmpty) return worldPath;
  final holesPath = ui.Path();
  for (final disc in discs) {
    final rawCenter = _pointToOffset(camera.latLngToScreenPoint(LatLng(disc.lat, disc.lon)));
    final pixelRadius = _metersToPixels(disc.radiusMeters, disc.lat, camera);   // 2 points à 1 m sur l'axe latitude
    holesPath.addOval(Rect.fromCircle(center: rawCenter - canvasOffset, radius: pixelRadius));
  }
  return ui.Path.combine(PathOperation.difference, worldPath, holesPath);
}
```
